Vibe Code: the Gap Between Intent and LLM's Implementation

I am a bit late in publishing this experience with the O3-mini-high reasoning model, but this blog captures nuances that matter while vibe coding.

I was new to the HPC domain, and my goal was simple: implement a First Come First Serve (FCFS) scheduling policy so I could compare it against other strategies e.g., Shortest Job First (SJF), including LLM-based schedulers. FCFS schedules jobs in arrival order, subject to resource availability, without reordering or prioritization.

What the LLM Actually Built

Across multiple iterations, O3-mini-high produced several schedulers. At first glance, they all looked aligned with pure FCFS. Closer inspection revealed three distinct behaviors.

1. FCFS with Opportunistic Scheduling (Near-Pure FCFS)

Jobs were processed in submission order and scheduled as soon as resources became available. There was no reordering, and jobs were not skipped for smaller ones. This was the closest to strict FCFS.

2. Greedy FIFO Backfilling

The scheduler scanned the waiting queue in arrival order and scheduled any job that fit, allowing later jobs to bypass earlier blocked jobs. This improved utilization and throughput, but it was no longer strict FCFS.

  • Earlier jobs did not strictly block the queue.
  • Smaller jobs behind them could slip through.
  • Idle resources were backfilled opportunistically.

3. Size-Based Greedy Backfilling

In a few cases, the model introduced sorting based on CPU, memory, and walltime, which prioritized smaller and shorter jobs.

  • Higher utilization and throughput.
  • Reduced fairness for larger jobs.
  • Clear deviation from FCFS.

This is essentially a greedy packing heuristic, which is efficient but not FCFS.

The Confusing Part

I evaluated all implementations using performance metrics like wait time, turnaround time, utilization, throughput, and Jain's fairness index. Different implementations produced conflicting outcomes, despite originating from the same prompt. The model's interpretation of the prompt and its internal heuristics led to emergent behaviors that were not explicitly intended.

Key Insights

  • LLMs optimize for syntactic correctness and local heuristics, not formal policy guarantees.
  • Without explicit constraints, LLMs drift toward efficiency-oriented heuristics such as backfilling.
  • Small structural implementation changes can lead to very different scheduling behavior.
  • Domain-relevant metrics and baseline comparisons are essential for validation.

The key gap is one has to consider what AI is building for you within technical constraints. The model can produce code that behaves correctly but the developer has to ensure that it does implement the intended behavior.
